Custom WebDAV sync

WebDAV sync uses your endpoint account over HTTPS. The sync document and local WebDAV state are encrypted with the extension Vault (AES-GCM-256, PBKDF2-SHA256, 600,000 iterations). The original Vault passphrase is never stored.

Data use and third-party disclosure: When you sync, this extension sends the configured WebDAV username/password and encrypted sync ciphertext to the third-party WebDAV endpoint you enter. The endpoint operator can still see the account, URL, timing, ciphertext size and ETag, but cannot read the sync document without the Vault material. Basic authentication credentials remain visible to the WebDAV service as the transport account. Sync requires an unlocked Vault; locking stops alarms and cancels in-flight requests.

Example: https://webdav.example.net/dav/multipass-sync.json

Configure a WebDAV file URL to begin.

All WebDAV endpoints must use HTTPS, including localhost, 127.0.0.1 and [::1]. WebDAV stores an encrypted sync envelope; the server still sees Basic account credentials and request metadata. Legacy plaintext remote files are refused by automatic sync and are never silently overwritten; download a backup first, then use explicit Push local migration only after review. Files larger than 5 MiB are rejected. Automatic sync uses a common baseline and strong ETags; if both devices change, the remote file is deleted, a snapshot is empty, or the server does not return reliable ETags, automatic sync stops for review. Browser alarms may run later than the selected interval.

Clear all credentials

This local-clear action requires confirmation and removes local credentials, temporary credential form data, WebDAV account/settings, sync metadata, backups, automatic-sync status, and persistent Vault root key material. It does not delete remote WebDAV files or files already downloaded to your computer; delete those separately.
