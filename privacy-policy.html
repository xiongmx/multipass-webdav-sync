Privacy Policy for MultiPass WebDAV Sync

Publisher: xiongmx
Effective date: 28 October 2026

This privacy policy describes version 1.1.4 of the unofficial MultiPass WebDAV Sync extension. It does not imply store approval or that every browser/device has been tested.

Information the extension handles

The extension handles information that you enter or that is needed to provide its authentication and optional synchronization features:

  • Website URL-matching rules and the HTTP Basic usernames and passwords you save for those rules.
  • The URL and authentication-challenge details of a request being considered for a matching rule. The extension may also read the active tab URL and tab identifier to display its status.
  • If you enable WebDAV synchronization, the HTTPS WebDAV file URL, WebDAV account username and password, your chosen synchronization interval, and synchronization metadata such as ETags and revision information.

The extension does not read the text or form contents of visited pages. It has no analytics, advertising, telemetry, developer-operated collection endpoint, or browser-account synchronization service.

How the information is used and shared

When a website issues an origin-server HTTP Basic authentication challenge that matches one of your rules, the extension sends the corresponding username and password to that website. HTTPS encrypts this traffic; plain HTTP does not encrypt the credentials in transit. Use HTTP only with trusted sites and prefer HTTPS. Proxy-authentication and non-Basic challenges are rejected.

WebDAV is optional and requires your explicit authorization on each device. When enabled, the extension sends the WebDAV account credentials in an HTTP Basic Authorization header over HTTPS to the endpoint you configure, and uploads or downloads a client-encrypted synchronization file. The original vault password is not sent to the WebDAV provider.

The WebDAV provider can observe the WebDAV account/authorization information, the endpoint, request timing and size, and synchronization metadata such as ETags. The synchronization file contents are encrypted by the extension and are not intended to be readable by the provider without the vault password. ETags and hashes help detect changes and conflicts; they are not encryption and do not prevent a malicious rollback.

The extension does not sell your data or transfer it to third parties for purposes unrelated to the extension's single purpose. Data is sent to the challenged website or the WebDAV endpoint you choose only as needed for the authentication or synchronization feature you use.

Encryption and storage

Version 1.1.4 uses AES-GCM-256 with a random 16-byte salt and 12-byte IV. A user-selected vault password is first processed with SHA-256 and then used as input to PBKDF2-HMAC-SHA-256 with 600,000 iterations. The original vault password is not stored. To keep the Vault unlocked after browser or app restarts, password-derived root material is stored locally in the extension profile and is cleared when you click Lock Vault. Until you lock it, anyone with access to the browser profile or extension context may use the Vault and decrypt local data or remote sync ciphertext; do not use this behavior on a shared device. The passphrase and WebDAV password are not stored as part of this feature.

Local credential rules, WebDAV account values, temporary values, backups, metadata, JSON exports, and WebDAV synchronization files are encrypted by the extension in version 1.1.4. Forgetting the vault password has no recovery backdoor. These statements describe the current implementation and do not claim an independent cryptographic audit or store certification.

Retention and your controls

Local data remains in the browser extension profile until you remove it or uninstall the extension. You can revoke WebDAV authorization, which stops scheduled synchronization and clears the locally stored WebDAV account, synchronization metadata, and local backups. Revoking authorization does not delete a remote WebDAV file or copies you have already downloaded or exported; remove those separately.

Creating the vault migrates legacy local data into encrypted storage, but the extension cannot guarantee secure erasure of old bytes in browser, device, or system backups. An existing plaintext remote file is not automatically adopted or overwritten; any migration requires a deliberate user action, and the original remote copy must be removed separately.

Locking the vault stops new credential responses and synchronization attempts. It cannot recall credentials or writes already sent, clear the browser's HTTP-authentication cache, or revoke sessions maintained by a website or WebDAV server.

Security and availability

Use HTTPS endpoints and trusted websites. WebDAV servers must support GET, PUT, conditional requests, and strong ETags for the synchronization safety checks. Browser alarms are best-effort and may run later than the selected interval. Synchronization stops on conflicts, missing or inconsistent baselines, weak or missing ETags, remote deletion, or other safety checks rather than silently choosing the latest timestamp.

This extension has not been independently security-audited. Automated tests do not constitute a security certification or guarantee compatibility with every WebDAV server or browser.
